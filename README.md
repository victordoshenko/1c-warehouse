# 1С: Учебное портфолио — учёт товаров и интеграция с внешним API

Учебный проект для демонстрации навыков разработки на платформе **1С:Предприятие 8.3/8.5**.  
Выполнен в **Конфигураторе**, исходники хранятся в формате **XML-выгрузки** (единый репозиторий, единый формат).

## 📦 Что в репозитории

Репозиторий содержит **одну конфигурацию**, в которой последовательно реализованы два проекта:

| Проект | Что демонстрирует |
|---|---|
| **Проект 1. Учёт товаров** | Справочники, документы, регистры накопления, отчёты на СКД, валидация на сервере |
| **Проект 2. Интеграция с внешним API** | Исходящий HTTP-запрос, JSON-сериализация, разбор ответа, обработка ошибок |

История коммитов показывает эволюцию: сначала базовая конфигурация, затем — интеграция.

## 🧩 Проект 1. Учёт товаров (базовая конфигурация)

### Что реализовано
- Справочник «Номенклатура» с валидацией артикула и цены на уровне объекта.
- Перечисление «Типы номенклатуры» (Товар / Услуга / Материал).
- Документ «Поступление товаров» с табличной частью и проведением по регистру.
- Регистр накопления «Остатки товаров» (вид: Остатки).
- Отчёт на СКД «Остатки товаров» с параметром периода и вычисляемым полем «Средняя цена».

### Архитектурные решения
1. **Валидация на сервере.** Проверка количества и цены выполняется в `ОбработкаПроведения`, а не в форме. Это защищает от подмены данных клиентом — тот же принцип, что и валидация на бэкенде в C#/Java.
2. **Сумма считается при проведении.** В табличной части `Сумма` — это кэш, синхронизируется с движением регистра. Источник истины — регистр.
3. **Запрос к регистру через виртуальную таблицу `Остатки`.** Используется параметр `&Период` — это позволяет строить отчёт на любую дату, а не только на текущую.

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    // 1. Очищаем старые движения (обязательно!)
    Движения.ОстаткиТоваров.Записывать = Истина;
    
    // 2. Проходим по табличной части
    Для Каждого СтрокаТЧ Из Товары Цикл
        // Валидация
        Если СтрокаТЧ.Количество <= 0 Тогда
            Отказ = Истина;
            Сообщение = Новый СообщениеПользователю;
            Сообщение.Текст = "Количество должно быть положительным (строка " + СтрокаТЧ.НомерСтроки + ")";
            Сообщение.Сообщить();
            Продолжить;
        КонецЕсли;
        
        // 3. Создаём движение
        Движение = Движения.ОстаткиТоваров.Добавить();
        Движение.ВидДвижения = ВидДвиженияНакопления.Приход;
        Движение.Период = Дата;
        Движение.Номенклатура = СтрокаТЧ.Номенклатура;
        Движение.Количество = СтрокаТЧ.Количество;
        Движение.Сумма = СтрокаТЧ.Количество * СтрокаТЧ.Цена;
        
        // 4. Синхронизируем сумму в ТЧ (чтобы пользователь видел)
        СтрокаТЧ.Сумма = Движение.Сумма;
    КонецЦикла;
КонецПроцедуры
```

### Ключевой фрагмент: запрос к регистру
```sql
ВЫБРАТЬ
    ОстаткиТоваровОстатки.Номенклатура КАК Номенклатура,
    ОстаткиТоваровОстатки.КоличествоОстаток КАК КоличествоОстаток,
    ОстаткиТоваровОстатки.СуммаОстаток КАК СуммаОстаток
ИЗ
    РегистрНакопления.ОстаткиТоваров.Остатки(&Период, ) КАК ОстаткиТоваровОстатки
```

## 🔌 Проект 2. Интеграция с внешним API (исходящий HTTP-запрос)

### Что реализовано
- Обработка `ИнтеграцияСВнешнимAPI` с формой и кнопкой «Отправить данные».
- Сбор данных из справочника «Номенклатура» (из Проекта 1).
- Сериализация в JSON через `ЗаписьJSON` (без ручной конкатенации строк).
- POST-запрос через `HTTPСоединение` + `ЗащищенноеСоединениеOpenSSL` (HTTPS) на `httpbin.org/post`.
- Таймаут 30 секунд (защита от «зависания» 1С при недоступности сервера).
- Обработка ошибок: сетевые сбои, таймаут, HTTP 4xx/5xx, некорректный JSON.
- Разбор ответа через `ЧтениеJSON` / `ПрочитатьJSON` (чтение в `Соответствие`, чтобы корректно обрабатывать ключи с дефисами, например `Content-Length`).
- Обработка поля `data`, которое приходит как строка с экранированным JSON — выполняется повторный парсинг и вывод в читаемом виде.

### Архитектурные решения
1. **Разделение слоёв:** сбор данных → сериализация → отправка → разбор ответа. Каждый шаг — отдельная функция. Это позволяет тестировать и переиспользовать код.
2. **Использование GUID** (`УникальныйИдентификатор`) для идентификации объектов — стандарт для связывания 1С с внешними системами.
3. **Явный таймаут** — без него 1С может зависнуть навсегда при недоступности сервера.
4. **Обработка исключений на каждом этапе** — сеть, HTTP, JSON.
5. **Чтение JSON в `Соответствие`** (`ПрочитатьJSON(..., Истина)`), а не в `Структуру` — это позволяет корректно обрабатывать ключи с дефисами (`Content-Length`), которые недопустимы в именах полей `Структуры`.

### Ключевой фрагмент: отправка POST с JSON
```bsl
Запрос = Новый HTTPЗапрос("/post");
Запрос.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
Запрос.УстановитьТелоИзСтроки(ДанныеJSON, КодировкаТекста.UTF8,
    ИспользованиеByteOrderMark.НеИспользовать);
Ответ = Соединение.ОтправитьДляОбработки(Запрос);
```

### Параллели с опытом в C#/Java
- `HTTPСоединение` + `ЗащищенноеСоединениеOpenSSL` — аналог `HttpClient` с `SslStream` в .NET. Таймаут — обязательный параметр, как в `HttpClient.Timeout`.
- `ЗаписьJSON` / `ПрочитатьJSON` — аналог `System.Text.Json` / `Jackson`. Сериализация через платформенные объекты, а не ручная конкатенация — это защита от инъекций и ошибок экранирования.
- Обработка `КодСостояния` 4xx/5xx — стандартная практика HTTP-клиентов. 4xx — ошибка клиента (неверные данные), 5xx — ошибка сервера (временная, можно retry).

## 🚀 Как развернуть

1. Скачайте платформу **1С:Предприятие 8.3/8.5** (подойдёт версия для обучения).
2. Создайте пустую информационную базу.
3. Откройте её в Конфигураторе.
4. Выберите **Конфигурация → Загрузить конфигурацию из файлов** и укажите папку `src/Configuration/` (или `Configuration.xml`, если используете этот вариант).
5. Обновите конфигурацию БД (`F7`) и запустите (`F5`).

### Как проверить Проект 1
- Откройте справочник «Номенклатура», добавьте 5–7 записей.
- Создайте документ «Поступление товаров», добавьте строки, проведите.
- Откройте отчёт «Остатки товаров» — убедитесь, что остатки отображаются.

### Как проверить Проект 2
- Откройте обработку «Интеграция с внешним API».
- Нажмите «Отправить данные».
- Убедитесь, что в поле результата появился JSON-ответ от `httpbin.org` (блок `json` и блок `data` в читаемом виде).
- Для проверки обработки ошибок отключите интернет и нажмите кнопку снова — должно появиться сообщение о сетевой ошибке.

## 📌 Что демонстрирует это портфолио

- Понимание объектной модели 1С (справочники, документы, регистры, отчёты).
- Умение строить запросы к виртуальным таблицам и настраивать СКД.
- Навык исходящих HTTP-интеграций и работы с JSON.
- Инженерную культуру: разделение слоёв, обработка ошибок, таймауты, использование GUID.
- Способность развивать существующую кодовую базу (Проект 2 вырос из Проекта 1), а не только создавать всё с нуля.
